# Группы, участники, расходы и долги

Код: `src/groups/` (`groups.schemas.ts`, `groups.service.ts`, `ledger.ts`, `repositories/`), схема —
`src/database/schema/groups.schema.ts`, `expenses.schema.ts`. Клиент —
[groups-and-members.md](../../../frontend/docs/architecture/groups-and-members.md),
[expenses.md](../../../frontend/docs/architecture/expenses.md).

## Группы и участники

- `groups` и `group_members`. Участник с `user_id = NULL` — pending: добавлен по имени, кошелька нет. Позже его
  «забирают» персональным приглашением ([invites.md](invites.md)).
- Доступ к группе есть только у участников. Чужая, несуществующая группа и кривой id дают один и тот же 404
  (`ParseUUIDPipe` с `exceptionFactory` → 404; проверка членства — в том же запросе, что и данные).
- Имена (`humanText` в `groups.schemas.ts`): NFC, пробелы схлопнуты, без управляющих и bidi-символов (U+202E
  переворачивает текст и годится для подмены). В группе имена уникальны без учёта регистра
  (`unique (group_id, lower(display_name))`).
- Лимиты: `MAX_GROUPS_PER_USER = 100`, `MAX_MEMBERS_PER_GROUP = 50`. Они проверяются под блокировкой строки
  пользователя или группы (`.for('update')`), поэтому параллельные запросы их не обходят.
- Имя создателя по умолчанию — короткий адрес (`Ccrt…KY47`), пока в профиле нет имени.
- Адрес участника для переводов — самый ранний Solana-кошелёк его аккаунта.

## Расходы

- `expenses` и `expense_shares`. Суммы — целые центы доллара (`integer`). API принимает доллары числом, но больше
  двух знаков после запятой — 400, а не тихое округление (zod-transform в центы).
- Сумма долей обязана равняться сумме расхода до цента; участник встречается в долях не больше одного раза.
- Плательщик и доли — участники **этой** группы. Это проверяет сервис (422), и это же гарантирует база через
  составные внешние ключи `(group_id, member_id) → group_members(group_id, id)`.
- Исходная валюта, сумма и курс (`original_currency`, `original_amount`, `original_rate`) должны давать ту же сумму в
  долларах с точностью ±1 цент, иначе 400: нельзя показать в ленте «10 000 ₸», а записать $1000. Сам курс сервер
  пока не сверяет с рынком — это появится вместе с `/rates`.
- Деление на доли считает клиент (без копеек для ₸ и ₽); сервер проверяет только сумму.
- Плательщик и доли — только **действующие** участники (без `left_at`), иначе 422.

### Правка и удаление

```
GET    /api/groups/:id/expenses/:expenseId   → расход + splitMode, shares (все участники), canEdit, updatedAt
PUT    /api/groups/:id/expenses/:expenseId   тело как при создании → ExpenseView
DELETE /api/groups/:id/expenses/:expenseId   → 204
```

- Править и удалять может **автор** (`expenses.created_by`) или **плательщик** (участник с `user_id` того, кто
  спрашивает). Остальным — 403. В списках у каждого расхода есть `canEdit` для того, кто спрашивает.
- Правка заменяет расход целиком: поля обновляются, старые доли удаляются, новые вставляются. Всё в одной
  транзакции под блокировкой группы и строки расхода (`editAccess` в `drizzle-expenses.repository.ts`).
- Долги не хранятся, поэтому после правки и удаления журнал пересчитывается сам.
- Уже созданные запросы оплаты сумму не меняют: если долг стал меньше, запрос стоит отменить и создать заново.
- Чужая группа — 404 «Группа не найдена», нет расхода — 404 «Расход не найден».

### Выход из группы и удаление участника

```
DELETE /api/groups/:id/members/:memberId   → { left: boolean }
```

- Свой `memberId` — выйти; чужой — удалить участника **без кошелька**. Участника с кошельком выгнать нельзя
  (403): он выходит сам.
- Только если у участника нет долгов ни перед кем и ему никто не должен (`debtsOf` по журналу после зачёта),
  иначе 409. Проверка — внутри транзакции под блокировкой группы (`loadDebtTotals(tx, …)`).
- Удаление мягкое: `left_at = now`, `user_id = NULL`. Строка остаётся — на неё ссылаются старые расходы.
  Доступ к группе пропадает сразу (членство ищется по `user_id`); вернуться можно по ссылке — это будет
  новая строка участника.
- Ушедший пропадает из списков, счётчиков и лимита участников; его имя снова свободно.
- Заодно его открытые запросы оплаты отменяются, а персональные ссылки на него отзываются.

## Журнал долгов

Долги **не хранятся**. `ExpensesRepository.debtTotals` при каждом чтении собирает суммы по парам «кто → кому»:

- из каждой доли расхода: «участник должен плательщику» (свою долю плательщик себе не должен);
- из каждой записи `payments`: перевод «должник → получатель» входит как обратный долг и гасит прямой.

`ledger.ts` (`netDebts`, `debtsOf`) зачитывает пары встречно: если A должен B 30, а B должен A 10, остаётся
«A → B 20». Это чистая функция, она покрыта юнит-тестами (`ledger.spec.ts`). `GroupsService.ledgerFor` отдаёт
этот журнал модулю payments, чтобы суммы запросов и расчётов считались из того же источника.

## Ответы

- `GET /me/overview` — итог «тебе должны / ты должен» по всем группам, группы с балансом и `myMemberId`, лента
  «Недавнее» (расходы, изменившие твой баланс, и переводы с `signature`).
- `GET /groups/:id/overview` — действующие участники, твой баланс, долги после зачёта, расходы с `canEdit`.
- В ленте у переводов `type`: `payment` — найден в сети (есть `signature`), `cash` — возврат наличными.

Формат ответов должен совпадать с zod-схемами фронтенда (`frontend/src/shared/api/groups/schemas.ts`).
