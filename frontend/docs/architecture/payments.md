# Рассчитаться и Запросить

## Рассчитаться — `/groups/:groupId/settle`

```
выбор (кому, сколько, USDC/USDT) → prepare → подпись в кошельке → submit → готово
```

1. **Выбор.** Список — долги «от меня» из `GroupOverview.debts`. Сумму можно уменьшить
   (частичный расчёт), больше долга — нельзя. Участник без кошелька (`address: null`) неактивен,
   рядом ссылка на участников — позвать его подключить кошелёк. Баланс кошелька —
   `GET /wallets/:address/balances`; не хватает — кнопка заблокирована.
2. **`POST /groups/:id/settlements`** `{ token, payer, transfers }` — бэкенд перепроверяет долги и
   собирает **одну** транзакцию: по SPL-переводу на получателя (+ создание его токен-счёта,
   если нет) и memo с id группы. Ответ — неподписанная транзакция base64, как при входе.
3. **Подпись.** `adapter.sign()` через тот же `WalletAdapter`, перед этим `useWalletGuard`:
   подписывает только аккаунт сессии, иначе модалка «Переподключить».
4. **`POST /groups/:id/settlements/:id/submit`** `{ signedTransaction }` — бэкенд отправляет в сеть,
   ждёт подтверждения и **сверяет переводы в блокчейне**, только потом закрывает долги.
   Фронтенду на слово не верим.
5. **Готово.** Инвалидируются `groups` и `payments`: баланс группы, главная, «Недавнее»,
   баланс кошелька. Ссылка на Solscan с учётом сети (`explorerTxUrl`).

Долги хранятся в долларах, поэтому неважно, платят USDC или USDT. Адреса токенов —
`shared/config/stablecoins.ts`; в devnet USDT нет — форма так и скажет.

**Мок** собирает memo-транзакцию с текстом переводов (в сеть не уходит), проверяет подпись
ed25519 и сразу засчитывает переводы. На экране «Готово» вместо ссылки на Solscan —
пометка «мок: в сеть не отправлялась».

## Запросить — `/groups/:groupId/request`

1. Должники — долги «мне». Сообщение, «напомнить через 3 дня».
2. **`POST /groups/:id/payment-requests`** → на каждого: `url` страницы запроса и `solanaPayUrl`:
   `solana:<мой адрес>?amount=32.00&spl-token=<mint>&reference=<ключ>&label=Divra&message=…`
3. Экран отправки: QR (это и есть `solanaPayUrl`, его сканируют Phantom/Solflare), копирование,
   Telegram, WhatsApp, системное «Поделиться».

`reference` — случайный публичный ключ. Бэкенд ищет по нему подписи
(`getSignaturesForAddress(reference)`), находит оплату, даже если друг платил прямо из кошелька
мимо Divra, проверяет сумму и токен, закрывает запрос и долг.

«Напомнить» — отложенная задача на бэкенде плюс канал уведомлений (в приложении / Telegram-бот).
В моке значение только отправляется.

## Экран друга — `/r/:code`

Открывается без входа (`SessionGate access="any"`). `GET /payment-requests/:code` → кто просит,
сколько, группа, сообщение. «Оплатить в кошельке» — ссылка `solana:`; на десктопе без кошелька
— QR для телефона. Divra деньги не держит: перевод идёт напрямую получателю.

В моке данные запроса зашиты в код ссылки (как у приглашений), поэтому страница работает
в другом браузере. Раздел «Из чего сумма» из макета пока не сделан — у мока нет данных группы
на стороне друга; бэкенд сможет отдать разбивку.
