# Рассчитаться и Запросить

## Рассчитаться — `/groups/:groupId/settle`

```
выбор (кому, сколько, USDC/USDT) → prepare → подпись в кошельке → submit → готово
```

1. **Выбор.** Список — долги «от меня» из `GroupOverview.debts`. Сумму можно уменьшить
   (частичный расчёт), больше долга — нельзя. Участник без кошелька (`address: null`) неактивен,
   рядом ссылка на участников — позвать его подключить кошелёк. Баланс кошелька —
   `GET /wallets/:address/balances`; не хватает — кнопка заблокирована.
2. **`POST /groups/:id/settlements`** `{ token, payer, transfers }` — бэкенд перепроверяет долги и
   собирает **одну** транзакцию: по SPL-переводу на получателя (+ создание его токен-счёта,
   если нет) и memo с id группы. Ответ — неподписанная транзакция base64, как при входе.
3. **Подпись.** `adapter.sign()` через тот же `WalletAdapter`, перед этим `useWalletGuard`:
   подписывает только аккаунт сессии, иначе модалка «Переподключить».
4. **`POST /groups/:id/settlements/:id/submit`** `{ signedTransaction }` — бэкенд отправляет в сеть,
   ждёт подтверждения и **сверяет переводы в блокчейне**, только потом закрывает долги.
   Фронтенду на слово не верим.
5. **Готово.** Инвалидируются `groups` и `payments`: баланс группы, главная, «Недавнее»,
   баланс кошелька. Ссылка на Solscan с учётом сети (`explorerTxUrl`).

Долги хранятся в долларах, поэтому неважно, платят USDC или USDT. Адреса токенов —
`shared/config/stablecoins.ts`; в devnet USDT нет — форма так и скажет.

**Мок** собирает memo-транзакцию с текстом переводов (в сеть не уходит), проверяет подпись
ed25519 и сразу засчитывает переводы. На экране «Готово» вместо ссылки на Solscan —
пометка «мок: в сеть не отправлялась».

## Запросить — `/groups/:groupId/request`

1. Должники — долги «мне». Сообщение, «напомнить через 3 дня».
2. **`POST /groups/:id/payment-requests`** → на каждого: `url` страницы запроса и `solanaPayUrl`:
   `solana:<мой адрес>?amount=32.00&spl-token=<mint>&reference=<ключ>&label=Divra&message=…`
3. Экран отправки: QR (это и есть `solanaPayUrl`, его сканируют Phantom/Solflare), копирование,
   Telegram, WhatsApp, системное «Поделиться».

`reference` — случайный публичный ключ. Бэкенд ищет по нему подписи
(`getSignaturesForAddress(reference)`), находит оплату, даже если друг платил прямо из кошелька
мимо Divra, проверяет сумму и токен, закрывает запрос и долг.

### Отправленные: напомнить и отменить

Открытый запрос из «Отправленных» открывается заново (QR и ссылка), под ним — `SentRequestActions`:

- **Напомнить** — `POST /groups/:id/payment-requests/:code/remind` возвращает готовый текст со ссылкой.
  Он уходит в системное «Поделиться» (телефон) или в буфер обмена (компьютер). Сервер разрешает
  одно напоминание в сутки на запрос (429), в списке видно «напоминал сегодня».
  Своих уведомлений (email, push, бот) нет: напоминание отправляешь сам, в привычный мессенджер.
- **Отменить запрос** — `DELETE /groups/:id/payment-requests/:code`. Ссылка отвечает 410 «Запрос отменён»,
  из «Отправленных» запрос пропадает. Долг остаётся — его можно запросить снова.

Поле «напомнить через 3 дня» в форме запроса пока только сохраняется: автоматических напоминаний нет.

### Вернули наличными (`pages/group`, `CashDialog`)

В «Кто кому» строка должника (тот, кто должен **тебе**) кликабельна: окно «Вернул наличными»,
сумма в долларах, по умолчанию весь долг. `POST /groups/:id/cash-payments { memberId, amount }`.

- Отмечает только тот, кому должны: должник сам себе долг не закроет (бэкенд ответит 409).
- Больше долга — 422.
- Открытый запрос этому участнику закрывается: сумма покрыта — запрос «оплачен наличными»
  (без ссылки в Solscan), частично — отменяется (новый запрос — на остаток).
- В ленте «Недавнее» — «Наличными от …».

## Экран друга — `/r/:code`

Открывается без входа (`SessionGate access="any"`). `GET /payment-requests/:code` → кто просит,
сколько, группа, сообщение. «Оплатить в кошельке» — ссылка `solana:`; на десктопе без кошелька
— QR для телефона. Divra деньги не держит: перевод идёт напрямую получателю.

В моке данные запроса зашиты в код ссылки (как у приглашений), поэтому страница работает
в другом браузере. Раздел «Из чего сумма» из макета пока не сделан — у мока нет данных группы
на стороне друга; бэкенд сможет отдать разбивку.

## Реализация на бэкенде

С `VITE_GROUPS_MOCK=false` всё это работает через `backend/` (подробно — `backend/README.md`, разделы
«Запросы на оплату» и «Рассчитаться»).

- **Запросить.** Сумму считает сервер: весь долг после зачёта. Получатель — только свой кошелёк. Оплату сервер
  находит в сети по `reference` при открытии страницы оплаты (страница спрашивает статус раз в 5 с) и в фоне.
  У должника один действующий запрос: та же сумма — тот же запрос, новая сумма — старый помечается «заменён».
- **Оплата со страницы.** Расширения на компьютере не открывают ссылки `solana:`, поэтому на `/r/:code` есть
  кнопка «Оплатить в Phantom». Бэкенд собирает перевод (`POST /payment-requests/:code/transaction`), кошелёк
  подписывает, бэкенд отправляет (`…/submit`). Ссылка и QR остаются для телефона.
- **Отправленные** (`GET /groups/:id/payment-requests`): мои запросы со статусом «ждёт / оплачен / истёк»,
  ссылкой и подписью транзакции. Ждущий запрос открывается заново — та же ссылка и QR.
- **Рассчитаться.** Сервер собирает одну транзакцию на всех выбранных (до 8), ждёт подтверждения и засчитывает
  только переводы, которые сеть реально провела. Не дождался — 503, фоновая проверка досверит позже.
- **Балансы** кошелька (`GET /wallets/:address/balances`) — только для своих кошельков.
- Подпись транзакции показывается ссылкой на Solscan: на странице оплаты, в «Отправленных», в «Недавнем».

## Переводы мимо Divra

Участник группы может вернуть долг прямо из кошелька, без ссылки Divra. Бэкенд замечает такой перевод в потоке
LaserStream (gRPC Helius) и создаёт подсказку получателю — подробно в
[backend/docs/architecture/transfers-and-events.md](../../../backend/docs/architecture/transfers-and-events.md).

- **Где видно:** `features/detected-transfers` — карточки над группами на главной и над «Кто кому» в группе
  (там только переводы, которые можно засчитать в эту группу). Не больше трёх, остальные — «Ещё N».
- **Карточка:** «Тимур перевёл тебе 30 USDC · из кошелька, мимо Divra · Solscan», «Засчитать в „Бурабай"?
  Тимур должен тебе 32 USDC». Если он должен в нескольких группах, на главной есть выбор группы
  (по умолчанию — с самым большим долгом).
- **Засчитать** — `POST /detected-transfers/:id/apply { groupId }`: засчитывается не больше долга, долг и лента
  обновляются. **Это не за долг** — `POST /detected-transfers/:id/dismiss`.
- **Откуда берутся:** `GET /me/detected-transfers`. Обновляются событием `transfer.detected` (WebSocket),
  а на случай, если событие не дошло, — раз в минуту.
- **Настройка:** Настройки → Профиль → «Замечать переводы мимо Divra» (`PATCH /me { detectTransfers }`).
- **Мок:** Настройки → Фича-флаги → «Имитировать перевод мимо Divra» — первый, кто тебе должен, «переводит»
  половину долга; карточка появляется через событие мока, как через WebSocket.
