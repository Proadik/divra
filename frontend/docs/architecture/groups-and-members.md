# Группы и участники («друзья»)

Статус: **способы 1 и 2 реализованы** (ссылка-приглашение и добавление по имени, на моке API).
Способы 3 и 4 — проект. Группа пока одна (`GROUP_ID = 'current'`).

## Почему «по имени без кошелька» нам подходит

Учёт расходов и долгов живёт на бэкенде (офчейн), кошелёк нужен только для перевода USDC.
Поэтому участник без кошелька (`pending`) может полноценно участвовать в расходах, а перевести
ему деньги физически нельзя — нет адреса. Риска для средств нет. Ограничения:

- «Рассчитаться» с `pending`-участником недоступно; в «Кто кому» он помечен «без кошелька».
- Подключиться он может только по **персональной** ссылке — тогда он забирает своего участника
  с историей, а не появляется вторым.
- Персональную ссылку нельзя создать для участника, который уже `active`.

## Что сделано

| Где                                | Что                                                                                          |
| ---------------------------------- | -------------------------------------------------------------------------------------------- |
| `pages/members` (`/group/members`) | Список с статусами, «Создать ссылку», «Ссылка» у участника без кошелька, «Добавить по имени» |
| `pages/join` (`/join/:code`)       | Превью приглашения без входа; «Вступить в группу» или «Подключить кошелёк»                   |
| `shared/api/groups/members-*.ts`   | zod-схемы и функции: `addMember`, `createInvite`, `getInvitePreview`, `acceptInvite`         |
| `shared/lib/pending-invite`        | Код приглашения в `sessionStorage` на время входа (проверяется zod)                          |
| `app/router/SessionGate`           | Доступ `any` для `/join/:code`; после подтверждения кошелька возвращает к приглашению        |
| Главная                            | Пункт меню «Участники и приглашения», подзаголовок «N участников» ведёт туда же              |

Поделиться ссылкой — системным окном (Web Share API, если есть) или копированием в буфер.

### Выход, удаление участника, отзыв ссылок (`pages/members`)

| Действие                       | Кто может      | Условие                                 | API                                    |
| ------------------------------ | -------------- | --------------------------------------- | -------------------------------------- |
| Удалить участника без кошелька | любой участник | у него нет долгов и ему никто не должен | `DELETE /groups/:id/members/:memberId` |
| Выйти из группы                | сам участник   | то же самое                             | `DELETE /groups/:id/members/<свой id>` |
| Отозвать ссылку-приглашение    | любой участник | ссылка действует                        | `DELETE /groups/:id/invites/:code`     |

- Участника с кошельком удалить нельзя (403): он выходит только сам.
- С долгами — 409 с текстом «Сначала рассчитайтесь…», он показывается в окне подтверждения.
- После выхода группа пропадает со всех экранов, переход на главную. Вернуться — по ссылке.
- Действующие ссылки — `GET /groups/:id/invites`, блок «Действующие ссылки» внизу страницы.
- Удалённый участник остаётся в старых расходах, но пропадает из списков и формы расхода;
  его имя снова свободно.

### Как ведёт себя мок

- Данные (участники, приглашения, расходы, долги) лежат в `localStorage` под ключом
  `divra.mock-db`: переживают перезагрузку и общие для вкладок одного браузера.
  Сбросить демо-данные — удалить этот ключ.
- Код приглашения в моке самодостаточный: 8 случайных символов + группа, участник и срок
  в base64url (поэтому лимит кода — 256 символов). Ссылка открывается и в другом браузере
  (инкогнито, телефон), где своей базы нет. У настоящего бэкенда код — короткая случайная строка.
- Пользователь в моке один и уже в группе: общая ссылка отвечает «Ты уже в этой группе»,
  персональная имитирует друга — участник становится `active`.
- Базы разных браузеров не синхронизируются: если друг принял ссылку в другом браузере,
  в твоём участник останется «без кошелька». Это исчезнет с настоящим API.

## Главная идея

Друг — это не аккаунт в соцсети, а **участник группы**. Деньги в Divra ходят on-chain, поэтому
«настоящий» участник — тот, кто подтвердил кошелёк тем же входом, что и ты
(подключить → подписать). Но вести расходы удобно сразу, ещё до того, как друг дошёл до приложения.
Поэтому у участника два состояния:

| Статус    | Кто это                                   | Что можно                                                               |
| --------- | ----------------------------------------- | ----------------------------------------------------------------------- |
| `pending` | Добавлен по имени, кошелька ещё нет       | Участвует в расходах и долгах. «Рассчитаться» с ним нельзя — нет адреса |
| `active`  | Зашёл по приглашению и подтвердил кошелёк | Всё. Видит группу, добавляет расходы, переводит USDC                    |
| `left`    | Вышел (только при нулевом балансе)        | Остаётся в истории расходов                                             |

```ts
type Member = {
  id: string
  displayName: string // как его назвал создатель или он сам
  status: 'pending' | 'active' | 'left'
  wallet: { chain: ChainId; address: string } | null // null, пока pending
  role: 'owner' | 'member'
  invitedBy: string // id участника
}
```

## Способы добавить друга

### 1. Ссылка-приглашение (основной)

1. «Пригласить» в меню группы → `POST /groups/:id/invites` → `{ code, url, expiresAt }`.
2. Ссылка `https://<домен>/join/<code>` уходит через Web Share API (Telegram, WhatsApp, iMessage),
   копированием или QR-кодом на экране — удобно, когда сидите рядом.
3. Друг открывает ссылку → видит превью группы (`GET /invites/:code`: название, кто пригласил,
   сколько участников) → проходит обычный вход: кошелёк → подпись.
4. После подтверждения фронт вызывает `POST /invites/:code/accept` → друг становится `active`.

Маршрут `/join/:code` доступен без входа. Если сессии нет, код кладём в `sessionStorage`
(`divra.pending-invite`), ведём через `/connect` → `/verify`, а после `verified`
`SessionGate` возвращает на `/join/:code`, где приглашение принимается.

Код: случайный, ≥ 128 бит, срок жизни (по умолчанию 7 дней), лимит использований,
отзывается создателем. Ссылка на группу не раскрывает ничего, кроме превью.

### 2. Добавить по имени (сразу, без кошелька)

Чтобы записать «Тимур заплатил за бензин» прямо в дороге: `POST /groups/:id/members { displayName }`
→ участник `pending`. Потом создатель отправляет Тимуру **персональную** ссылку
(`/join/<code>?claim=<memberId>`): при входе Тимур «забирает» этого участника вместе со всей историей
и долгами, а не появляется вторым.

### 3. По адресу кошелька

Вставить адрес Solana, `.sol`-домен (SNS) или отсканировать QR адреса из кошелька.
Создаётся участник `pending` с уже известным адресом: с ним можно сразу рассчитаться,
а при входе с этим адресом он автоматически становится `active`.
Без ссылки человек не узнает о группе, поэтому этот способ дополняет приглашение, а не заменяет.

### 4. Из прошлых групп

«Друзья» = люди, с которыми ты уже был в группах (`GET /me/contacts`, считает бэкенд).
Новую группу можно собрать в пару тапов. Отдельной «дружбы» с запросами и подтверждениями нет —
связь появляется сама после общей группы.

## Правила

- Удалить участника может владелец, и только при нулевом балансе; иначе — «выйти» с погашением.
- Участник `pending` не может быть плательщиком в переводе USDC (нет адреса) —
  кнопка «Рассчитаться» показывает «ждёт подключения» и предлагает отправить ссылку.
- В форме расхода `pending`-участники выбираются так же, как `active`.
- Один адрес — один участник в группе. Попытка принять приглашение тем же адресом возвращает
  существующего участника.

## API (черновик)

| Метод                              | Назначение                                                         |
| ---------------------------------- | ------------------------------------------------------------------ |
| `POST /groups/:id/invites`         | Создать приглашение `{ maxUses?, expiresInDays?, claimMemberId? }` |
| `GET /invites/:code`               | Превью группы для экрана приглашения (без входа)                   |
| `POST /invites/:code/accept`       | Принять (нужна сессия)                                             |
| `DELETE /groups/:id/invites/:code` | Отозвать                                                           |
| `POST /groups/:id/members`         | Добавить по имени или адресу `{ displayName, wallet? }`            |
| `GET /me/contacts`                 | Люди из прошлых групп                                              |

Все схемы — zod в `shared/api/groups`, как у остальных запросов.

## Куда это ляжет во фронте

```
pages/join/             превью приглашения и принятие
pages/group-members/    список участников, «Пригласить», «Добавить по имени»
features/invite-member/ создание ссылки, Web Share, QR (используется в шапке и в списке)
entities/member/        тип Member, бейдж статуса, аватар
```

## Главная и маршруты

| Путь                            | Страница                                                      | Данные                                    |
| ------------------------------- | ------------------------------------------------------------- | ----------------------------------------- |
| `/`                             | `pages/home` — итог по всем группам, список групп, «Недавнее» | `GET /me/overview` → `homeOverviewSchema` |
| `/groups/:groupId`              | `pages/group` — баланс, кто кому, расходы                     | `GET /groups/:id/overview`                |
| `/groups/:groupId/expenses/new` | `pages/add-expense`                                           | `POST /groups/:id/expenses`               |
| `/groups/:groupId/members`      | `pages/members`                                               | `POST /groups/:id/members`, `/invites`    |

- Пути строят хелперы `groupPath`, `addExpensePath`, `membersPath` из `shared/config`.
- «Добавить расход» на главной: одна группа — сразу в её форму, несколько — модалка «В какую группу?», ни одной — создание группы.
- Новая группа (`POST /groups`: название и тип `trip | home | food | other`) открывается на странице участников, чтобы сразу позвать друзей.
- Мутации инвалидируют весь `groupKeys.all`: расход в группе меняет и итог на главной.
- Мок хранит несколько групп (`divra.mock-db`, версия 3). Базу версии 2 переносит в группу «Алматы → Бурабай», старый id `current` указывает туда же.
