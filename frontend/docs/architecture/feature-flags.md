# Фича-флаги

## Что есть

| Флаг          | Включён                                           | Выключен (по умолчанию)                                         |
| ------------- | ------------------------------------------------- | --------------------------------------------------------------- |
| `mock.groups` | демо-группы, расходы, участники (`divra.mock-db`) | пустая база (`divra.mock-db:empty`) — как у нового пользователя |
| `mock.rates`  | демо-курсы KZT/RUB                                | курсов нет, работает только ввод в USD                          |

По умолчанию данных нет: так приложение видит новый пользователь. Флаги включают демо-данные.

Флаги работают внутри мок-бэкенда. Мок или настоящий бэкенд — решает `VITE_API_MOCK`;
с настоящим бэкендом данные приходят из него, флаги mock.* ни на что не влияют.

Обе мок-базы сохраняются: можно создать группу в пустой, включить демо, вернуться — она на месте.
Начать заново — «Сбросить мок-данные» в Настройках → Фича-флаги.

Список — в `shared/config/flags.ts`. Новый флаг = новая запись там.

## Как устроено

```
источник (база) ──load / subscribe / опрос──▶ store (zustand) ──▶ isFlagOn() в API-функциях
                                                   │              useFlag() в компонентах
                                                   └─ изменились значения ──▶ resetQueries
```

- **`shared/lib/feature-flags/store.ts`** — значения из источника; нет ключа — дефолт из конфига.
  Последние значения кэшируются в `localStorage` (`divra.flags-cache`), чтобы после перезагрузки
  первые запросы шли туда же, куда шли.
- **`isFlagOn(name)`** мок читает в момент запроса, а не при сборке.
  Поэтому смена флага действует со следующего запроса — без перезагрузки.
- **`app/state/FeatureFlagsSync.tsx`** — запускает синхронизацию и, когда итоговое значение флага
  изменилось, делает `resetQueries` по его ключам (`QUERIES_BY_FLAG`). Экраны тут же
  перезапрашивают данные. `reset`, а не `invalidate`: данные из другого набора показывать нельзя даже секунду.
- Приложение рендерится после первого ответа источника или через 1,5 с — на кэше/дефолтах.

## Источники

`VITE_FLAGS_SOURCE`: `local` (по умолчанию при `VITE_API_MOCK=true`) или `remote`.

- **local** — «база» в `localStorage` (`divra.mock-flags`). Переключатели в Настройках → «Фича-флаги»
  пишут в неё; другие вкладки узнают через событие `storage` мгновенно.
- **remote** — бэкенд:
  - `GET /flags` → `{ "mock.groups": false, "mock.rates": true }` — только то, что задано в базе;
    неизвестные ключи и не-boolean игнорируются;
  - опрос раз в `VITE_FLAGS_POLL_MS` (30 с) и при возвращении во вкладку;
  - с `VITE_FLAGS_STREAM=true` — ещё `GET /flags/stream` (Server-Sent Events): изменение доходит
    за доли секунды, опрос остаётся страховкой.

## Что нужно на бэкенде, чтобы «поменял в базе — приложение подтянуло»

1. Таблица:
   ```sql
   create table feature_flags (
     name       text primary key,
     enabled    boolean not null,
     updated_at timestamptz not null default now()
   );
   ```
2. `GET /flags` — `select name, enabled from feature_flags` → объект `{ name: enabled }`.
   Можно отдавать `ETag` по `max(updated_at)`, чтобы опрос был дешёвым.
3. Для мгновенного применения — `GET /flags/stream` (`Content-Type: text/event-stream`):
   - триггер на таблице делает `pg_notify('feature_flags', '')`;
   - сервер слушает `LISTEN feature_flags` и на каждое уведомление шлёт всем подключённым
     `data: {...все флаги...}\n\n`;
   - раз в ~25 с — комментарий `: ping\n\n`, чтобы прокси не рвали соединение.
     Без SSE всё тоже работает — через опрос, с задержкой до 30 с.
4. На фронте: `VITE_FLAGS_SOURCE=remote`, `VITE_FLAGS_STREAM=true`.

Фронт ничего не знает о БД: ему нужен только контракт `GET /flags` (+ поток).
Можно заменить таблицу на Unleash / GrowthBook / LaunchDarkly — достаточно отдавать тот же JSON.

## Оговорки

- **Моки попадают в прод-сборку** отдельными чанками: грузятся только при включённом флаге,
  но лежат на сервере. Если это нежелательно — добавить build-time переменную и вырезать
  `import('../mock/…')` в прод-сборке.
- Флаги сейчас глобальные. Флаги «для конкретного пользователя/процента» — на стороне бэкенда:
  `GET /flags` отдаёт уже вычисленные значения для текущей сессии.
