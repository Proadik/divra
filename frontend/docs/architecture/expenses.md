# Расходы

## Форма «Добавить расход» (`pages/add-expense`, маршрут `/expenses/new`)

```
lib/split.ts            расчёт долей (чистые функции, покрыты тестами)
lib/masks.ts            маски Maskito и парсинг чисел
model/use-expense-form  состояние формы, валидация zod, мутация TanStack Query
ui/AddExpensePage       экран; ui/SplitMembers, ui/CategoryPicker, ui/MaskedInput
```

Поля: сумма, «Что» (до 60 символов), «Платил» (по умолчанию — ты), категория,
способ деления и участники. «Сканировать чек» — заглушка (TODO: OCR).
После сохранения сводка группы перезапрашивается (`invalidateQueries`), и пользователь
возвращается на главную.

## Маски (Maskito)

| Поле                | Параметры `maskitoNumber`                                                 |
| ------------------- | ------------------------------------------------------------------------- |
| Сумма, точные суммы | 2 знака после точки, разделитель тысяч — пробел, `,` → `.`, 0 … 1 000 000 |
| Проценты            | то же, максимум 100                                                       |
| Доли                | целые 0 … 99                                                              |

- Объекты масок создаются один раз в `lib/masks.ts`: `useMaskito` пересоздаёт маску при смене объекта.
- Поле контролируемое: значение — отформатированная строка, обновление по событию `input`
  (так рекомендует Maskito для React). Число получаем через `maskitoParseNumber`.

## Как делится сумма

Всё считается в **центах**, чтобы не ловить ошибки float.

| Режим   | Ввод     | Правило                                                              |
| ------- | -------- | -------------------------------------------------------------------- |
| Поровну | —        | `distribute(total, [1, 1, …])`                                       |
| Точно   | суммы    | сумма вводов должна равняться итогу, иначе «Осталось распределить X» |
| %       | проценты | ровно 100%, иначе «Осталось распределить X%»                         |
| Доли    | целые    | пропорционально, хотя бы одна доля > 0                               |

`distribute` — метод наибольших остатков: каждый получает целую часть, оставшиеся центы
достаются участникам с большей дробной частью, при равенстве — первым в списке.
100 USDC на троих → 33.34 / 33.33 / 33.33. Сумма долей всегда равна сумме расхода.

## Контракт API

`POST /groups/:id/expenses` — схема `createExpenseRequestSchema` (`shared/api/groups/schemas.ts`):

```json
{
  "title": "Ужин у костра",
  "category": "food",
  "paidById": "me",
  "amount": 120,
  "splitMode": "percent",
  "shares": [
    { "memberId": "me", "amount": 60 },
    { "memberId": "dana", "amount": 24 },
    { "memberId": "timur", "amount": 24 },
    { "memberId": "aigerim", "amount": 12 }
  ]
}
```

Фронт отправляет **итоговые доли**, а `splitMode` — чтобы форма редактирования показала исходный способ.
zod проверяет, что сумма долей равна сумме расхода (в центах). Бэкенд обязан перепроверить то же
и что все `memberId` состоят в группе.

Мок (`shared/api/mock/groups.ts`) ведёт долги парами с взаимозачётом и пересчитывает
баланс и «Кто кому» — изменения видны на главной до перезагрузки вкладки.
